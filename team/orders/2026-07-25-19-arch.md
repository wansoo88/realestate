## 목적 (왜 하는가)
증설이 어렵고(사용자 확정) 서버 여유가 332MB뿐이라, 전체 스택 대신 **최소 구성으로 배포 준비**한다.
worker.py 가 미구현이라 추천 비동기는 아직 안 도니, **1차 배포는 동기 기능(인증·프로필·자금계산·지도)**
만 올린다. worker·redis 는 추천 실구현 때 2차. 이러면 PM판단2(worker 무한재시작)도 자동 해소된다.

⚠️ **이 지시는 '준비'까지다. 실제 서버 반영은 G5(사람 승인) 후.** 서버엔 실서비스(autobtc·itsmine)가
돈다 — 준비물(스크립트·설정)을 만들되, 서버 상태를 바꾸는 명령은 PM 보고 후 사람 승인받아 실행한다.

## 근거
- 사용자 결정: 최소 구성 + itsmine 중지 (증설 불가)
- 서버 실측: available 332MB, 스왑 2GB, 기존 host nginx 가동, autobtc 195MB·itsmine 68MB
- `docs/03-build/code-review-log.md` PM판단1·2, `backend/app/worker.py`(미구현)

## 작업
- [ ] **배포용 compose** (`docker-compose.deploy.yml` 또는 override): **api + db 만**.
      · db: postgis, 포트 미노출, 명명 볼륨, mem_limit(예 256m)
      · api: 127.0.0.1:<포트> 바인드(호스트 nginx가 프록시), mem_limit(예 200m), memswap=mem
      · nginx·worker·redis 컨테이너 **제외**(nginx는 호스트 것 재사용, worker/redis는 2차)
      · 우리 프로젝트 컨테이너 이름/네트워크가 기존(autobtc·itsmine)과 **충돌 안 하게** 접두어
- [ ] **호스트 nginx 서버블록**(`deploy/nginx-realestate.conf`): `realestate.utilverse.info`
      → `127.0.0.1:<api포트>` 프록시 + 프론트 정적(`frontend/dist`) 서빙 + TLS(certbot) + 기존
      보안헤더/‑rate limit. **기존 서버블록(itsmine 등) 안 건드림.**
- [ ] **itsmine 중지 스크립트**(`deploy/pause-itsmine.sh`): `docker stop` 만(삭제·볼륨제거 금지),
      복구 스크립트(`resume-itsmine.sh`)도 쌍으로. 되돌릴 수 있어야 한다.
- [ ] **배포 절차 문서**(`deploy/DEPLOY.md`): 순서(키 생성→compose up db→마이그레이션→api→nginx
      reload→헬스체크), 롤백, 리소스 확인 명령. **각 단계가 사람이 승인/실행할 수 있게** 명시.
- [ ] **.env 생성 안내**: JWT_SECRET·FIELD_ENCRYPTION_KEY 생성 커맨드(이미 .env.example 에 있음),
      MOLIT_API_KEY 는 발급 후. 서버 `.env` 는 커밋 금지(당연).
- [ ] **리소스 사전점검 스크립트**(`deploy/preflight.sh`): 배포 전 available 메모리·디스크·포트충돌·
      기존 컨테이너를 찍어 **안전 여부를 사람이 판단**할 수 있게.

## 완료 기준 (DoD — 검증 가능하게)
- `docker compose -f docker-compose.deploy.yml config` 가 문법 통과(로컬).
- 배포 구성이 api+db 만이고 상시 메모리 상한 합계가 **여유(itsmine 중지 후 ~400MB) 안**에 든다(계산 제시).
- DEPLOY.md 만 보고도 사람이 순서대로 실행/롤백할 수 있다.
- 실제 서버 반영 명령은 **문서·스크립트로만** 존재하고, 이 작업에서 서버를 바꾸지 않는다.

## 경계 (하지 말 것)
- **서버 상태 변경 금지**(컨테이너 기동/중지, nginx reload, 파일 배치) — 전부 G5 후.
