## 목적 (왜 하는가)
MVP 5종 중 `location-analyst` 가 지금 입지 데이터가 없어 항상 "판단 보류"를 낸다.
공간쿼리 기반 입지 분석 로직을 설계·구현해 F1(입지 통합)·F5(선호/기피)를 실동작시킨다.
동시에 F4 의 동별 추정 로직(좌표 기반, 신뢰도 낮게)을 구체화한다.

## 작업
- [ ] `backend/app/domain/location/` — 순수 함수로(공간 계산은 리포지토리가 좌표 제공):
      · 학군: 학구도 내부 여부(거리 아님), 통학 거리, 대로 횡단 여부
      · 교통: 최근접역 거리·노선수, 신설노선 호재(status·confidence 필수)
      · 인프라: 마트·병원(응급실 구분)·공원 거리
      · 유해요소: 간선도로 소음·철도·유해시설 반경 → **기피는 제외**(가점 상쇄 아님)
- [ ] 교통 호재는 착공 전이면 `confidence ≤ 0.4`. "GTX 개통 예정"을 확정 호재로 쓰지 말 것.
- [ ] 동별 추정: 동 좌표 기준 역/학교/도로 거리로 **상대 점수만**. 금액 환산 금지.
      `basis: estimated_from_location`, `confidence ≤ 0.6` 강제.
- [ ] `orchestrator.py::location_finding` 을 실제 로직에 연결(리포지토리 인터페이스 필요 시
      PM 경유로 re-arch 에 요청 — 직접 base.py 수정 금지).
- [ ] 테스트: 학구도 포함/미포함, 호재 신뢰도, 기피 제외, 동별 신뢰도 상한.

- 학군이 거리가 아니라 학구도 포함 여부로 판정된다(테스트).
