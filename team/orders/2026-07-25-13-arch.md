## 목적 (왜 하는가)
re-review 가 SR-008/SR8-1(high, **배포 차단**)을 발견했다. Argon2id 기본값이 해시당 64MiB 라
로그인 동시 5건(nginx burst=5)이면 320MiB — 이 서버 여유(332MB)를 거의 다 먹어 **동거 실서비스가
OOM**된다. 실제 pytest 8회 중 1회 HashingError 관측. 유출은 없으나(전역 500) 가용성 위협이다.

## 근거
- `docs/03-build/security-review-log.md` SR-008 / `.review-state.json` open_findings SR8-1
- `backend/app/core/security.py` (Argon2 PasswordHasher 기본값)
- `docker-compose.yml` (backend 메모리 제한 없음)
- OWASP Password Storage Cheat Sheet: Argon2id 권장 하한 **19MiB / t=2 / p=1**

## 작업
- [ ] **Argon2 파라미터 명시**: `PasswordHasher(memory_cost=19456(19MiB), time_cost=2,
      parallelism=1)` 로 낮춘다. 64→19MiB 라도 OWASP 권장 만족. 5동시=95MiB 로 3.4배 여유.
      → 파라미터를 설정(config)으로 빼서 서버 사양별 조정 가능하게.
- [ ] **compose 메모리 제한**: `docker-compose.yml` 의 api·worker 에 `mem_limit`(또는 deploy
      resources) 명시 → 우리 스택이 폭주해도 **동거 서비스로 번지지 않게**.
- [ ] **인증 경로 동시성 제한**: 해시 연산이 스레드풀 40 을 다 먹지 않게 세마포어 등으로
      의도한 값(예: 4~8)으로 제한. 로그인 폭주가 전체 워커를 마비시키지 않게.
- [ ] **회귀**: 기존 비밀번호 해시·검증 테스트가 새 파라미터로도 통과(argon2id prefix,
      hash≠verify). 파라미터 변경 후 기존 해시 검증 호환(argon2-cffi 는 파라미터를 해시에
      담으므로 자동 호환) 확인 테스트.
