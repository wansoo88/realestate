## A. 로더 스키마 확장

### 새 표현 3종
```yaml
lending:
  absolute_cap:                                   # 지역조건부 절대한도
    - { id: cap_capital_600m, when: { region_group: "수도권" },
        absolute_cap_krw: 600000000, source: ..., source_url: ..., as_of: ... }
  stress_dsr:                                     # 스트레스 DSR 가산금리
    - { id: stress_capital, when: { region_group: "수도권" },
        stress_rate_pct: 1.5, ... }

acquisition_tax:
  - id: std_6_9_small                             # 연속 누진 밴드
    when: { price_min: 600000001, price_max: 900000000, area_max: 85 }
    rate_pct: 2.0                                 # 폴백 대표값(하위호환)
    progressive: { basis: price, unit_krw: 100000000, coefficient: 0.666...,
                   constant: -3.0, min_rate_pct: 1.0, max_rate_pct: 3.0 }
    extras_ratio: { local_education_ratio: 0.1 }  # 지방교육세 = 본세×1/10 (연동)
```

### 노출 API (계산 아님, 값 제공만)
- `RuleSet.absolute_cap(**facts)` / `.absolute_cap_krw(**facts)` — 겹치면 **가장 작은 한도**
- `RuleSet.stress_rule(**facts)` / `.stress_rate_pct(**facts)` — 겹치면 **가장 높은 가산금리**
- `Bracket.rate_pct_for(**facts)` / `.total_rate_pct(**facts)` / `.is_progressive`
- `ProgressiveFormula.rate_pct_at(값)`

### 판단 근거 (왜 이렇게 했는가)
- **한도가 겹치면 최소값, 가산금리가 겹치면 최대값.** 둘 다 "보수적인 쪽"이다.
  한도를 크게 잡으면 빌릴 수 없는 돈을 빌릴 수 있다고 말하게 된다.
- **`min_rate_pct`/`max_rate_pct` 클램프를 필수로 강제**했다. 계수를 잘못 적으면 음수 세율이
  조용히 나가는데 그 오류는 수천만 원 단위다. 구간 경계에선 클램프가 곧 정답이기도 하다
  (6억→1.0%, 9억→3.0%).
- **음수 `stress_rate_pct` 는 로딩 거부.** 음수면 한도가 *늘어난다* — 오타 하나로 과대 산정.
- **`extras`(금액 대비 %)와 `extras_ratio`(본세 대비 배율)를 분리**했다. 누진 밴드에서
  지방교육세를 고정 %로 적으면 본세가 변해도 안 따라가서 조용히 틀린다.
- **폴백 `rate_pct` 를 필수로 남겼다.** engine 이 아직 안 바꿨어도 터지지 않고 현재의 근사
  결과를 낸다. 다만 이는 **L1 이 아직 안 닫혔다는 뜻**이기도 하다 — 아래 이슈 1 참조.

## 이슈 / 잔여 위험
1. **[중요] 로더 확장만으로는 실구매 가능액이 정확해지지 않는다.**
   engine 이 `_pct_total` → `total_rate_pct` 로 바꾸고, 절대한도를 `min` 후보에 넣고,
   스트레스 금리를 DSR 한도 계산에 적용해야 L1·L2 가 닫힌다. **지금은 여전히 과대 산정된다.**
   → re-domain 하달 필요(contract.md §3 체크리스트 5줄).
2. **`region_group` 사실이 아직 없다 — 이 확장의 유일한 선행 작업.**
   6억 한도가 수도권 조건부라 이 사실을 engine 이 안 넘기면 규칙이 있어도 매칭되지 않는다
   (로더 원칙상 조용히 미적용). `PropertyFacts` 에 추가가 필요한데 re-domain 소유라
   손대지 않았다. 파생 규칙(법정동코드 앞 2자리 `11`/`41`/`28` → 수도권)을 문서에 적어 뒀다.
3. **003 은 실행 검증 안 됨.** CR-008 은 001·002 까지만 실검증했다. 003 의 `GeometryType()`
   CHECK 제약은 PostGIS 함수가 IMMUTABLE 이어야 성립하는데(확인상 IMMUTABLE), 실제 적용은
   해봐야 안다. `needs_db` 5건이 이걸 검증하도록 준비돼 있다.
4. 전체 테스트 중 argon2 `HashingError` 로 1건이 **간헐 실패**하는 걸 관측했다(재실행 시 통과).
   메모리 할당 실패로 보이며 동시 실행 중인 다른 에이전트와의 자원 경합이 유력하다.
   내 변경과 무관하나(argon2 미접촉) 서버 환경에서 재발하면 Argon2 파라미터 조정이 필요할
   수 있어 남긴다.
