## 결과 (한 문단)
1차 배포(api+db) 준비물 **6종**을 만들었다. **서버는 전혀 건드리지 않았다** —
ssh·rsync·docker 명령을 한 번도 실행하지 않았고(로컬에 docker 자체가 없다),
서버 상태를 바꾸는 모든 동작은 `DEPLOY.md` 의 절차와 스크립트로만 존재한다.
메모리는 **api 192 + db 192 = 384MB** 로 잡아 itsmine 중지 후 여유 400MB 안에 들어간다
(남는 여유 16MB). 여유가 얇아서 `ARGON2_CONCURRENCY=2`(38MB 절약)와 nginx 인증
rate limit 을 **메모리 방어선으로** 함께 걸었다. 백엔드 회귀 293 passed / 실패 0.

## 메모리 계산 (DoD 핵심)

| 항목 | 상한 | 실사용 추정 근거 |
|---|---:|---|
| `realestate-db` | **192 MB** | shared_buffers 64 + wal 2 + 백엔드 20×~3 + 상시 ~20 ≈ **146MB** (여유 46) |
| `realestate-api` | **192 MB** | 파이썬 런타임 ~120 + Argon2 2×19MiB=38 ≈ **158MB** (여유 34) |
| **합계** | **384 MB** | |

| 시나리오 | 여유 | 판정 |
|---|---:|---|
| 지금 그대로 | 332 MB | ❌ **부족** (384 > 332) |
| itsmine 중지 후 | 332 + 68 = **400 MB** | ✅ **16 MB 남음** |

**db 기본값으로는 안 들어간다.** postgres 기본 `shared_buffers` 가 128MB 라
그대로 두면 상한을 넘긴다 → compose 에서 튜닝값을 명시했다(64MB/max_conn 20/work_mem 2MB).
`memswap_limit = mem_limit` 이라 우리 컨테이너는 스왑을 쓰지 않는다 — 상한 초과 시
스왑으로 새며 호스트 전체를 느리게 만드는 대신 **컨테이너만 깔끔히 OOM-kill 되고 재시작**된다.
동거 서비스(autobtc)를 지키는 선택이다.

> 16MB 는 얇다. preflight 가 보고한 실제 available 이 400MB 에 못 미치면
> **배포를 보류**하도록 스크립트가 `[위험]` 을 찍고 문서도 그렇게 안내한다.

## 배포 중 발견해 막은 문제 2건 (그냥 올렸으면 터졌을 것들)

1. **이미지 안에 `config/tax_rules.yaml` 이 없다.**
   Dockerfile 빌드 컨텍스트가 `./backend` 라 저장소 루트의 `config/` 가 이미지에 안 들어간다.
   컨테이너 안 기본 경로는 `/srv/config/tax_rules.yaml` 인데 그 파일이 없다.
   **기동은 성공하고** `/affordability` 호출 시점에야 503 `TAX_RULES_UNAVAILABLE` 이 나서
   한참 뒤에 발견될 문제였다. → `./config:/srv/config:ro` 마운트로 해결.
   부수 효과로 **세율이 바뀌면 파일만 갈아끼우고 재시작**하면 된다(이미지 재빌드 불필요).

2. **서버에서 프론트를 빌드하면 안 된다.**
   vite/tsc 빌드가 이 서버 남은 메모리보다 많이 먹는다 — 빌드하다 **동거 실서비스가 OOM**
   될 수 있다. DEPLOY.md 를 "로컬 빌드 → `rsync dist/`" 로 못박았다.

## 판단 근거 (왜 이렇게 했는가)
- **override 가 아니라 독립 파일.** override 는 서비스를 더할 수는 있어도 **지울 수 없다.**
  이번 배포의 핵심이 nginx·worker·redis 를 **빼는 것**이라 독립 파일이 맞다.
- **`limit_req_zone` 이름에 `re_` 접두어.** 호스트 nginx 에 같은 이름 zone 이 있으면
  "duplicate zone" 으로 nginx 가 통째로 안 뜨고 — **동거 서비스까지 같이 죽는다.**
  같은 이유로 DEPLOY.md 는 reload 전에 `nginx -t` 를 반드시 거치게 했다.
- **`include /etc/nginx/proxy_params` 를 쓰지 않고 헤더를 직접 적었다.** 그 파일은
  배포판마다 있기도 없기도 한데, 없으면 `nginx -t` 가 실패한다. 의존을 없앴다.
- **인증 rate limit(1r/s)은 보안이자 메모리 방어선이다.** 로그인 1건마다 Argon2 가
  19MiB 를 잡으므로(SR8-1), 여기를 조이는 게 곧 메모리를 지키는 것이다.
- **`resume` 은 "이름이 itsmine 인 걸 전부 start" 하지 않는다.** pause 가 남긴 목록에
  있는 것만 켠다. 원래 꺼져 있던 컨테이너까지 켜면 그건 복구가 아니라 상태 변경이다.
  복구가 하나라도 실패하면 목록 파일을 **남긴다**(지우면 무엇이 안 돌아왔는지 잃는다).
- **api 는 `127.0.0.1` 바인드.** `0.0.0.0` 이면 공인 IP 에 인증 API 가 그대로 노출된다.

## 이슈 / 잔여 위험
1. **`docker compose config` 를 실제로 못 돌렸다.** 구조·문법은 검증했지만
   compose 스키마 수준 검증(예: 지원하지 않는 키)은 서버에서 첫 실행 때 드러난다.
   DEPLOY.md §5-2 가 `up -d db` 부터 시작하므로 문제가 있으면 거기서 멈춘다(피해 없음).
2. **여유 16MB.** 실측이 예상과 다르면 배포 보류가 맞다. preflight 가 판정한다.
3. **1차 배포 후에도 지도에 단지가 안 보인다** — 실데이터 수집이 2차라 DB 가 비어 있다.
   기능 결함이 아니라 의도된 상태이며 DEPLOY.md §7 에 명시했다. **사용자 안내 필요.**
4. **추천은 202 만 반환하고 완료되지 않는다**(worker 미구현). 같은 이유로 UI 에
   "구현 중" 표시가 유지돼야 한다 — re-ux/re-fe 확인 필요.
5. **DB 백업이 없다.** `pg_dump` 정기 백업 미설정. 자산 정보를 담는 서비스라
   2차에서 반드시 다뤄야 한다(FIELD_ENCRYPTION_KEY 백업도 함께).
6. **itsmine 중지는 사용자 서비스 하나를 내리는 일이다.** 되돌릴 수 있게 만들었지만
   중지 자체가 G5 승인 대상이다. `--dry-run` 을 먼저 돌리도록 문서에 넣었다.
7. 서버 하드닝(root SSH 차단·ufw·fail2ban, security.md §4)은 **이번 범위 밖**이며
   여전히 미적용이다. 배포와 별개로 남아 있다.
