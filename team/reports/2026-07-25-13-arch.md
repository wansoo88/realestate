## 결과 (한 문단)
Argon2id 파라미터를 argon2-cffi 기본값(64MiB·t3·p4)에서 **OWASP 권장 하한
(19MiB·t2·p1)** 으로 낮추고 설정화했다. 여기에 **인증 해시 동시성 제한(4)** 과
**compose 메모리 상한**을 더해, 최악 사용량이 **320MiB → 76MiB (4.2배 감소)** 가 됐다.
제한이 없던 기존 구조에서는 스레드풀 40 개가 전부 해시에 들어가면 **2.5GiB** 까지
갈 수 있었는데, 이제 세마포어가 76MiB 에서 자른다.
**보안은 낮추지 않았다** — 19MiB 는 OWASP 하한이고, 그 아래로는 아예 기동이 막히도록
이중으로 문을 달았다. 인증 폭주 시 인증만 503 으로 흘려보내 지도·리포트는 계속 응답한다.
반복 실행 **10회 전부 통과**(원 증상은 8회 중 1회 실패였다).

## 메모리 예산 (근거)
```
이전: 64MiB × 동시 5 = 320 MiB      ← SR8-1 이 지적한 값
이후: 19MiB × 동시 4 =  76 MiB      (4.2배 감소)

제한 없을 때 최악(스레드풀 40): 이전 2.5GiB → 이후 76MiB (세마포어 상한)
서버 관측 여유 332MB 대비 4.4배 여유
OWASP 하한 충족: m=19456≥19456, t=2≥2, p=1≥1
해시 1건 소요: 약 34ms (로그인 지연 무시 가능)
```

## 판단 근거 (왜 이렇게 했는가)
- **파라미터가 아니라 동시성을 줄이는 게 맞다.** 메모리가 모자랄 때 m 을 깎으면
  오프라인 크래킹 난이도가 그대로 내려간다. 동시성을 줄이면 **느려질 뿐 강도는 유지**된다.
  이 원칙을 코드·설정·`.env.example` 세 곳에 같은 문장으로 적어 뒀다.
- **하한을 두 겹으로 막았다.** `validate_runtime()` 은 기동 점검이라 호출을 강제할 수 없어,
  **실제로 해시를 만드는 길목**(`_build_hasher`)에도 문을 달아 예외를 던지게 했다.
  점검을 건너뛰어도 약한 파라미터로는 해시가 만들어지지 않는다.
- **대기 대신 503.** 슬롯을 무한정 기다리면 스레드풀 40 개가 전부 인증에 묶여
  지도·리포트까지 죽는다. 2초 안에 못 얻으면 **인증만** 거절한다.
  응답은 `BUSY` 한 종류뿐이라 계정 존재 여부는 드러나지 않는다.
- **재해시·마이그레이션이 필요 없다.** argon2 는 m·t·p 를 해시 문자열에 담고 검증 때
  거기 적힌 값을 쓴다. 운영 DB 에 64MiB 로 저장된 해시가 있어도 로그인이 깨지지 않는다
  (테스트로 고정).
- **`needs_rehash` 호출부를 만들지 않았다.** 파라미터를 *낮췄으므로* 옛 64MiB 해시가
  `True` 로 나오는데, 자동 재해시하면 **더 약한 해시로 내려간다.** 함수는 남기되
  쓰지 않고, 이유를 주석으로 박아 뒀다.
- **`memswap_limit` 을 `mem_limit` 과 같게** 뒀다. 안 그러면 한도를 넘겨도 안 죽고
  스왑으로 새어 서버 전체가 느려진다 — OOM 보다 진단이 어렵다.

## 이슈 / 잔여 위험
1. **[PM 판단 필요] 메모리 상한 합계가 서버 여유를 넘는다.**
   api 256 + worker 192 + worker 192 = **640MB** 이고 여기에 db·redis·nginx 가 더해진다.
   CR-008 이 관측한 여유는 **332MB** 다. 지시받은 "번짐 방지" 상한은 넣었지만,
   **이 상한만으로 전체 스택이 이 서버에 들어가지는 않는다.** 배포 전 사양 재검토가 필요하다
   (워커를 나중에 띄우거나, 스왑 확보, 또는 서버 증설). → G5 판단 사항.
2. **워커 재시작 루프 위험(기존 이슈, 이번 범위 밖).** `app/worker.py` 는 미구현이라
   종료코드 2 로 죽는데 compose 는 `restart: unless-stopped` 다. 지금 띄우면 무한 재시작이
   돌고, 메모리 상한이 있어도 CPU 를 계속 먹는다. 워커 구현 전까지 **띄우지 않는 게** 맞다
   (worker.py 주석도 같은 말을 한다). 배포 절차에 명시 필요.
3. **`mem_limit` 은 compose v2 non-swarm 전용 문법이다.** 이 프로젝트는 `docker compose up`
   을 쓰므로 맞지만, 나중에 swarm 으로 가면 `deploy.resources.limits` 로 바꿔야 한다.
4. **실제 컨테이너 기동 검증은 못 했다** — 로컬에 Docker 가 없다(03-arch 이후 동일).
   `mem_limit` 문법은 정적으로만 확인했다. 003 마이그레이션과 함께 서버 검증이 필요하다.

  용도를 다했다 — 법정 산식과의 **정확 일치**를 검증하도록 바꾸는 게 맞다.
