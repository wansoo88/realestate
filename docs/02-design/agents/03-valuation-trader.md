# 03. `valuation-trader` — 매매 전문가 (MVP)

> 공통 규약: [`README.md`](README.md)
> 담당 요구사항: **F4**(동·층·타입별 가치 차이) — 이 서비스의 차별점

## 목적
"이 물건, 지금 이 값이 적정한가"에 답한다. 같은 단지 안에서도 **어느 층·어느 타입·어느 동**이
싸고 잘 팔리는지 가른다. 비싸게 사거나 안 팔리는 물건을 잡는 걸 막는 게 목적이다.

## ⚠️ 능력의 한계를 먼저 명시한다

| 축 | 근거 | 신뢰도 |
|---|---|---|
| **층별** | 실거래 `floor` | **높음** (0.85~0.95) |
| **타입/면적별** | 실거래 `area_m2` | **높음** |
| **동별** | 좌표 기반 입지 추정 (실거래에 동 없음) | **낮음 (≤0.6)** — `basis: estimated_from_location` |
| 향·조망 | 동 좌표 + 방위각 | 낮음 |

> 동별 판단을 층별과 같은 확신으로 내놓으면 **G2 반려**다. `erd.md` §0 참조.

## 판단 로직

### A. 적정가 밴드 (규칙 계산)
```
모집단: 동일 complex_id + 동일 unit_type_id + 최근 N개월 (기본 6, 부족 시 12→24 확장)
       + is_cancelled = false
통계:  중위값, 사분위(P25/P75), 표본수 n
층 보정: 층대별(1-5 / 6-15 / 16+) 중위 비율을 곱해 대상 층 기준가 산출
밴드:  [P25 보정, P75 보정]
```
| 조건 | 처리 |
|---|---|
| `n < 5` | 밴드 산출 금지 → 인접 면적대·인접 단지로 확장하고 **확장했음을 표기** |
| 확장해도 부족 | `INSUFFICIENT_DATA` |
| 해제(취소) 거래 | **제외.** 포함하면 허위 신고가 시세를 왜곡한다 |

### B. 호가–실거래 갭
```
gap_pct = (호가 − 적정가 중위) / 적정가 중위
```
| 갭 | 해석 |
|---|---|
| ≤ −10% | 급매 후보 (단, `listing-researcher`의 `trust_score`가 **높아야** 신뢰 — 낮으면 미끼 의심) |
| −10% ~ +5% | 협상 여지 |
| ≥ +10% | 상단 — 근거 필요(리모델링·최상층·조망 등) |

### C. 환금성 (거래회전율)
```
회전율 = 최근 12개월 거래건수 / 해당 타입 총 세대수
현재 매물 적체 = active listings / 총 세대수
평균 소요일 = median(days_on_market)
```
> **환금성은 수익률만큼 중요하다.** 못 파는 자산은 오른 것도 의미가 없다.
> 특히 대형 평형·소규모 단지에서 이 지표가 갈린다.

### D. 동별 편차 (추정 — 신뢰도 낮게)
동 좌표 기준으로 계산:
- 지하철역 최단거리, 초등학교 최단거리(학구도 내부 여부)
- 간선도로 거리(소음 페널티), 공원·녹지 거리
- 단지 내 상대 위치(중앙/외곽), 방위각

→ 상대 점수만 낸다. **금액으로 환산하지 않는다.**
`"105동은 101동 대비 역까지 220m 가깝습니다(추정 근거: 좌표)"` 까지가 허용 범위.
`"105동이 3천만원 비쌉니다"` 는 금지.

## 데이터 의존
`trade`(파티션), `listing`, `unit_type`, `building`, `poi`(동별 추정용)

## 검증 포인트 (re-review)
- [ ] 해제 거래가 제외되는가
- [ ] `n < 5`에서 밴드를 내놓지 않는가
- [ ] 모집단 확장 시 그 사실이 출력에 표기되는가
- [ ] 동별 판단의 `confidence ≤ 0.6`이고 `basis`가 붙는가
- [ ] 동별 차이를 **금액으로 환산하지 않는가**
- [ ] 신고 지연 리스크가 항상 `risks`에 포함되는가
