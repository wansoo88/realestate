# UI/UX 설계 — 모바일 퍼스트

> 2단계 설계 산출물 · 2026-07-24
> 기준 화면: **폰 세로 360~430px**. 데스크톱은 확장이지 기준이 아니다.
> 사용자는 **이동 중에 폰으로 매물을 본다**고 가정한다.

---

## 0. 이 서비스 UX의 진짜 과제

지도 앱은 많다. 이 제품이 다른 점은 **"왜 이 매물인지"를 읽게 만드는 것**이다.
따라서 UX의 핵심 질문은 "지도를 어떻게 예쁘게 그리나"가 아니라 이 세 가지다.

1. **폰 한 화면에 지도와 리스트를 어떻게 같이 놓나** — 둘 다 필요한데 자리가 없다
2. **자산·소득·선호를 어떻게 물어보나** — 다 물으면 아무도 안 쓴다
3. **8종 에이전트 분석을 어떻게 읽히나** — 다 보여주면 아무도 안 읽는다

---

## 1. 설계 기준

| 항목 | 기준 | 이유 |
|---|---|---|
| 기준 폭 | 360px (갤럭시 기본) | 여기서 깨지면 다 깨진다 |
| 터치 타깃 | **최소 44×44px** | 지도 위 버튼은 특히 |
| 주요 액션 위치 | **화면 하단 1/3** | 엄지 도달 범위. 상단 헤더 버튼은 한 손으로 못 누른다 |
| 대비 | WCAG AA (본문 4.5:1) | |
| 다크모드 | 지원 | 매물은 밤에 본다 |
| 애니메이션 | `prefers-reduced-motion` 존중 | |
| 폰트 크기 | 본문 16px 이상 | 금액·근거를 읽는 앱이다 |

## 2. 화면 구조

```
[온보딩] → [지도 홈] ⇄ [단지 상세] → [추천 결과] → [리포트 상세]
                ↑                          ↑
           [조건 설정] ─────────────────────┘
```

| 화면 | 목적 |
|---|---|
| 온보딩 | 최소 조건만 받고 바로 지도로 (§4) |
| **지도 홈** | 메인. 지도 + 바텀시트 리스트 |
| 단지 상세 | 시세·층별 편차·매물·입지 |
| 추천 결과 | 순위 카드 리스트 |
| 리포트 상세 | 근거 전문 (why / why_not / next_actions) |
| 조건 설정 | 자산·선호·기피 |

## 3. 지도 ⇄ 리스트 — **바텀시트 3단 스냅**

폰에서 지도와 리스트를 나란히 놓을 공간이 없다. 탭으로 전환하면 맥락이 끊긴다.
→ **드래그 가능한 바텀시트**로 한 화면에서 비율을 바꾼다.

```
 peek (25%)              half (55%)              full (92%)
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│              │        │              │        │ ← 지도        │
│              │        │     지도      │        ├──────────────┤
│     지도      │        │              │        │ ▤ 매물 34건   │
│              │        ├──────────────┤        │ ┌──────────┐ │
│              │        │ ▤ 매물 34건   │        │ │ ○○아파트  │ │
│              │        │ ┌──────────┐ │        │ │ 14.8억   │ │
├──────────────┤        │ │ ○○아파트  │ │        │ ├──────────┤ │
│ ━━ 매물 34건  │        │ │ 14.8억   │ │        │ │ △△아파트  │ │
│ ○○아파트 14.8억│        │ ├──────────┤ │        │ │ 13.2억   │ │
└──────────────┘        └──────────────┘        └──────────────┘
   지도 탐색 중            둘 다 보기              리스트 정독
```

- 시트 손잡이(`━━`)는 **48px 높이 터치 영역**
- 지도를 움직이면 자동으로 `peek`으로 내려감 → 지도가 가려지지 않음
- 리스트 카드를 탭하면 지도 마커가 하이라이트 + 해당 위치로 이동
- **데스크톱**: 좌 지도 / 우 리스트 2단 고정 (시트 없음)

## 4. 마커 밀도 — 3단계 드릴다운

수도권 전체는 단지만 2만 개다. 다 찍으면 지도가 죽는다.

| 줌 | 표시 | 마커 내용 |
|---|---|---|
| ~12 | **구/시 군집** | `강남구 342` + 중위가 |
| 13~15 | **단지** | 단지명 + 대표가 |
| 16~ | **단지 + 동** | 동 위치 (추천된 동은 강조) |

- 군집 마커는 개수에 따라 크기 3단계
- **예산 초과 단지는 회색**으로 흐리게 — 지우지 않는다(왜 없는지 보이게)
- 추천 결과의 매물은 **순위 배지**(①②③)를 마커에 표시

## 5. 점진적 조건 입력 — 가장 중요한 UX 결정

자산·소득·기존대출·주택수·선호·기피를 온보딩에서 다 물으면 **거기서 이탈한다.**

### 3단계로 쪼갠다

```
[1단계 — 온보딩 30초]        [2단계 — 첫 추천 직전]      [3단계 — 쓰면서]
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│ 어디를 보시나요?     │     │ 더 정확하게 계산할까요?│     │ 이 매물 왜 빠졌죠?   │
│ [지역 선택]         │     │ · 연소득           │     │ → 기피조건 조정      │
│                    │     │ · 기존 대출        │     │ → 가중치 슬라이더    │
│ 예산은?             │     │ · 보유 주택수      │     │                    │
│ [대략 범위 슬라이더] │     │                    │     │ (사용 중 자연스럽게) │
│                    │     │ [나중에] [입력]     │     │                    │
│      [시작하기]     │     └────────────────────┘     └────────────────────┘
└────────────────────┘
   → 바로 지도 진입           → 건너뛰어도 서비스 동작       → 쓸수록 정교해짐
```

**원칙: 어느 단계에서 멈춰도 서비스가 동작해야 한다.**
- 1단계만: 예산 범위 기준 지도 탐색 가능
- 2단계까지: 정확한 실구매 가능 금액 + 세금 반영
- 3단계: 개인화된 순위

### 민감 정보 입력 화면의 신뢰 표시
자산·소득을 묻는 화면에는 **왜 필요한지와 어떻게 보관하는지**를 반드시 붙인다.
> "대출 한도와 세금을 정확히 계산하기 위해 필요합니다.
> 암호화해 저장하며 외부 AI에는 금액이 전송되지 않습니다."

이 한 줄이 없으면 사용자는 소득을 입력하지 않는다. (근거: `security.md` §6)

## 6. 근거 리포트 — 결론 먼저, 근거는 접기

8종 에이전트 분석을 한 번에 펼치면 아무도 안 읽는다.

```
┌────────────────────────────────┐
│ ① ○○아파트 84A          82점   │  ← 결론 (항상 보임)
│ 14.8억 · 101동(추정) · 9층      │
│                                │
│ "예산 내에서 학군·역세권을      │  ← headline 한 줄
│  모두 만족하는 후보입니다"       │
│                                │
│ ✅ 좋은 점                  ▼  │  ← 기본 펼침 (3개까지)
│  · ○○초 학구도 내 340m          │
│  · 중위 14.0억 대비 호가 5.7%↑  │
│    → 협상 여지                  │
│  · 취득비용 포함 8.42억          │
│                                │
│ ⚠️ 확인할 점                ▶  │  ← 기본 접힘, 배지로 개수 표시
│    3건                          │
│                                │
│ 📋 다음에 할 일             ▶  │
│    2건                          │
│                                │
│ [지도에서 보기]  [단지 상세]     │  ← 하단 = 엄지 범위
└────────────────────────────────┘
```

**규칙**
- `why_not`(확인할 점)은 **접혀 있어도 개수 배지로 존재를 알린다.** 숨기지 않는다.
- `why` 항목마다 **어느 에이전트 판단인지** 아이콘/라벨 노출 (근거 추적)
- 리포트 하단에 **면책 고지** 고정

## 7. 불확실성을 눈에 보이게 — 이 제품의 정체성

이 서비스는 확신을 파는 게 아니라 **판단 근거**를 판다. 그래서 **모르는 걸 모른다고 보여줘야 한다.**

| 상태 | 표기 | 예 |
|---|---|---|
| 실거래 기반 (확실) | 일반 텍스트 | `14.0억 (실거래 37건)` |
| **추정치** | `~` 접두 + 회색 | `~13.95억 (추정)` |
| **동별 판단** | `추정` 배지 + 신뢰도 점 | `101동 ●●○○○ 추정` |
| 데이터 없음 | 빈칸 아님, 명시 | `데이터 없음` (0원 아님) |
| 시차 있음 | 기준일 병기 | `2026-06-30 기준` |

### 실거래 지연 고지 (상시)
시세가 나오는 모든 화면에 작게:
> `실거래는 신고까지 최대 30일 걸립니다. 최근 거래는 반영되지 않았을 수 있습니다.`

## 9. 디자인 토큰 (초안)

```css
/* 색 — 의미 기반. 상승=빨강, 하락=파랑 (한국 금융 관습) */
--price-up: #d92d20;      --price-down: #1570ef;
--confident: #101828;     --estimated: #667085;   /* 추정치는 흐리게 */
--warn: #f79009;          --danger: #d92d20;

/* 간격 — 4px 그리드 */
--sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-6: 24px;

/* 타이포 */
--fs-body: 16px;   --fs-price: 20px;  --fs-caption: 13px;
--ff-num: "SF Mono", ui-monospace, monospace;   /* 금액은 등폭 — 자릿수 비교 */

/* 터치 */
--touch-min: 44px;  --sheet-handle: 48px;
```

> 금액에 **등폭 폰트**를 쓰는 이유: `14.8억`과 `13.2억`을 세로로 비교할 때 자릿수가 맞아야 읽힌다.

## 10. React Native 이식 고려

앱 확장이 확정이므로 **지금부터 경계를 나눠둔다.**

| 계층 | 재사용 | 비고 |
|---|---|---|
| API 클라이언트 · 타입 | ✅ 100% | 순수 TS |
| 상태관리 · 계산 로직 | ✅ 100% | 뷰 비의존 |
| 포맷터(금액·면적·날짜) | ✅ 100% | |
| 화면 컴포넌트 | ⚠️ 구조만 | RN은 `div`가 없다 |
| 지도 | ❌ 별도 | 웹: 카카오맵 JS SDK / 앱: 카카오맵 네이티브 SDK |
| 바텀시트 | ❌ 별도 | 웹: CSS / 앱: `react-native-bottom-sheet` |

**규칙: 비즈니스 로직을 컴포넌트 안에 쓰지 않는다.** 훅/스토어로 분리한다.

## 11. 접근성 체크리스트
- [ ] 터치 타깃 44px 이상
- [ ] 대비 AA 충족 (특히 `--estimated` 회색 텍스트)
- [ ] 지도 정보에 **리스트 대체 경로** 존재 (지도는 스크린리더로 못 읽는다)
- [ ] 포커스 순서가 시각 순서와 일치
- [ ] 색만으로 정보 전달 금지 (상승/하락에 부호 병기)
- [ ] `prefers-reduced-motion` 존중

---

## 12. 하지 않을 것 (다크패턴 금지)
- 특정 매물을 사도록 유도하는 긴급성 문구 (`지금 아니면 놓칩니다`)
- 리스크를 읽기 어렵게 만드는 배치
- 면책 고지를 사실상 안 보이게 처리
- 조건 입력을 강제해 이탈을 막는 설계
