와이어프레임 — 점진적 조건 입력 3단계

근거: ux/README.md §5(점진적 입력) · api-spec.md §2(/me/profile, /me/preferences) §3(/affordability)

이 화면의 원칙 — 어느 단계에서 멈춰도 서비스가 동작해야 한다. 자산·소득·기존대출·주택수·선호·기피를 온보딩에서 한 번에 물으면 거기서 끝난다. 그래서 묻는 시점을 "그 값이 실제로 필요해지는 순간"까지 미룬다.

전체 로그인 조건 입력 3단계 리포트 상세

1단계 — 온보딩 30초 · 지역 + 대략 예산만

왜 두 개만 묻나: 지도를 띄우려면 어디와 얼마만 있으면 된다. 소득·대출은 "정확한 실구매 가능 금액"을 계산할 때 필요한 값이고, 그건 아직 필요하지 않다. 여기서 받은 예산은 GET /map/complexes?max_price_krw= 로 바로 쓰인다.

구현 요건 (re-fe)
  • "건너뛰고 지도 보기"를 반드시 남긴다. 조건 입력을 강제해 이탈을 막는 건 다크패턴(README §12). 건너뛰면 예산 필터 없이 지도만 뜬다 — 그래도 동작한다.
  • 예산은 범위(min~max)로 받는다. 단일 상한만 받으면 "8억짜리를 찾는데 5억 매물"이 섞인다.
  • 슬라이더는 터치 타깃 44px 확보 + 숫자 직접 입력 대안을 함께 제공(정밀 조작은 슬라이더로 못 한다).
  • 모바일은 세로 1열, 데스크톱은 2열. 데스크톱에서 세로로 길게 늘어놓으면 스크롤이 생겨 손해.
  • 지역 칩은 <button aria-pressed> — 체크박스처럼 보이는 div 금지.

2단계 — 첫 추천 직전 · 소득 · 기존 대출 · 보유 주택수

왜 지금 묻나: 사용자가 "추천 받기"를 누른 바로 그 순간이 민감 정보를 요구할 수 있는 유일한 시점이다. 이 시점에는 사용자가 이미 지도를 보고 매물을 봤고, 무엇을 얻는지 알고 있다. 온보딩에서 물으면 대가 없이 소득을 요구하는 꼴이 된다.

구현 요건 (re-fe) — 이 화면은 G3(개인정보) 대상이다
  • [나중에]가 [입력]과 같은 크기·같은 시각 비중이면 안 되지만, 숨겨서도 안 된다. 고스트 버튼으로 명확히 보이게 두되 주 동작은 primary. 이게 다크패턴 경계선이다.
  • 금액은 만원 단위 입력 → 원 단위 정수로 변환해 전송(api-spec §0: 금액은 원 단위 bigint). 입력 중 toLocaleString으로 3자리 콤마를 넣되 커서 위치를 보존한다.
  • inputmode="numeric" — 모바일에서 숫자 키패드가 안 뜨면 소득 입력에서 이탈한다.
  • ⛔ 이 화면의 값은 어떤 경우에도 console.log·에러 리포팅·sessionStorage에 남기지 않는다 (api-spec §2 로그 제외 규정). 폼 상태는 컴포넌트 메모리에만.
  • 제출 실패 시 재입력 부담을 줄이려 값을 유지하되, 브라우저 자동완성 저장은 끈다 (autocomplete="off") — 공용 기기 대비.
  • 결과는 POST /affordability의 binding_constraint를 그대로 보여준다: "한도를 결정한 건 DSR입니다" — 왜 이 금액인지가 곧 신뢰다.

3단계 — 쓰면서 정교화 · "이 매물 왜 빠졌죠?"

왜 설정 화면이 아니라 결과 옆에 두나: 선호·기피는 추상적으로 물으면 못 답한다. "대로변 소음이 싫으신가요?"보다 "이 매물이 대로변이라 감점됐습니다 → 신경 안 씀"이 훨씬 정확하다. 조건 편집은 불만이 생긴 그 자리에서 일어나야 한다.

구현 요건 (re-fe)
  • 제외된 매물을 목록에서 지우지 않는다. "왜 없는지"가 보여야 조건을 고칠 수 있다 (README §4의 "예산 초과 단지는 회색으로" 와 같은 원칙).
  • 가중치 합계는 자동 정규화. 사용자에게 100 맞추기를 시키면 아무도 안 만진다. PUT /me/preferences 의 weights에 정규화된 값으로 보낸다.
  • 슬라이더 <input type="range">는 키보드 조작이 기본 제공된다 — 커스텀 div 슬라이더로 바꾸지 말 것(접근성 손실).
  • 조건 변경 → 재추천은 사용자가 명시적으로 누를 때만. 슬라이더를 만질 때마다 Claude API가 도는 건 비용 사고다 (architecture.md §6 비용 통제).
  • [저장하고 다시 추천] 버튼의 3건 변동 배지는 규칙 필터로 미리 계산 가능한 값만 표시한다 (예산·기피 필터). 점수 변동은 AI를 돌려야 알 수 있으므로 예고하지 않는다.
