와이어프레임 — 근거 리포트 상세

근거: ux/README.md §6(결론 먼저) §7(불확실성) §8(비동기 대기) · api-spec.md §5(GET /recommendations/{job_id})

이 화면이 제품의 전부다. 지도는 어느 앱에나 있다. 이 서비스가 파는 건 "왜 이 매물인가"와 "무엇이 확실하지 않은가"다. 따라서 설계 원칙은 하나 — 결론은 항상 보이고, 근거는 접히되 존재는 숨기지 않는다.

전체 로그인 조건 입력 3단계 리포트 상세

0. 분석 대기 — 45초를 버티게

왜 빈 스피너를 금지하나: 에이전트 5종이 Claude API를 왕복하면 수십 초가 걸린다(architecture.md §2.2). 모바일에서 45초짜리 스피너는 "멈춤"으로 읽힌다. 완료된 에이전트부터 순차 노출하면 같은 45초가 "일하는 중"으로 읽힌다.

구현 요건 (re-fe)
  • SSE(/recommendations/{id}/stream) 우선, 폴링 폴백 필수. 모바일 백그라운드 전환 시 SSE는 끊긴다(api-spec §9 A1). 복귀 시 GET으로 상태를 다시 맞춘다.
  • 진행률 텍스트에 role="status" aria-live="polite". 진행 바(.bar)는 aria-hidden — 같은 정보를 두 번 읽으면 방해가 된다.
  • 단계 이름은 에이전트 ID가 아니라 사용자 언어로. valuation-trader → "시세 분석".
  • 완료 단계에 산출된 값을 즉시 붙인다("8.5억"). 진행률만 도는 것보다 체감 대기가 훨씬 짧다.

1. 근거 리포트 상세

왜 "확인할 점"을 접어두면서 개수는 보여주나: 다 펼치면 아무도 안 읽고, 그냥 접으면 리스크를 숨긴 게 된다(다크패턴). 접되 3건 배지로 존재를 알린다 — 읽을지 말지는 사용자가 정하되, 있다는 사실은 감추지 않는다.

구현 요건 (re-fe) — 이 화면은 G2(근거 감사) 대상이다
  • 접기는 네이티브 <details>/<summary>로 구현한다. 키보드·스크린리더·브라우저 찾기(Ctrl+F)가 전부 공짜로 따라온다. 커스텀 아코디언은 셋 다 잃는다.
  • summary 높이 44px 이상. 접기 화살표만 누르게 만들면 안 된다 — 줄 전체가 타깃이다.
  • "확인할 점"은 절대 조건부 렌더링으로 사라지지 않게 한다. 0건이면 "확인할 점 없음"을 명시. 섹션이 사라지면 사용자는 리스크를 검토했는지 안 했는지 알 수 없다.
  • 각 근거에 어느 에이전트의 판단인지(findings[].agent_id)와 출처·기준일(evidence.source, as_of)을 반드시 붙인다. 출처 없는 evidence가 오면 그 항목을 렌더링하지 않는다(CHARTER §5-2).
  • 가격 표기 규칙은 components.md §3 <Price> 단일 컴포넌트로만. 화면마다 다르게 표기하면 추정치가 확정치로 새어 나간다.
  • 순위 배지 ①은 "가장 좋은 매물"이 아니라 "입력한 조건에서의 1순위"다. 조건 스냅샷(criteria_snapshot)을 항상 열람 가능하게 둔다 — 접힌 "이 판단의 조건" 섹션이 그것.
  • 모바일은 리스크를 접고, 데스크톱은 펼친다. 자리가 있는데 접는 건 숨기는 것에 가깝다.
  • ⛔ 긴급성 문구·카운트다운·"오늘의 추천" 배너 금지(README §12).
