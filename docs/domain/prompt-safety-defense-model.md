# 자산유출 방어 모델 (SR4-2) — 무엇이 주 방어이고 무엇이 보조 그물인가

> 작성: re-domain · 2026-07-25 · 근거 ORDER 2026-07-25-08-domain / SR-006 반려
> 대상 코드: `backend/app/agents/base.py`, `orchestrator.py`
> ⚠️ 이 문서는 **설계 근거의 정정 기록**이다. 정확성 판정(PASS/CLOSE)은 re-review(G2/SR) 소관이며
> 여기서 스스로 "해소"를 선언하지 않는다.

## 왜 이 문서가 필요한가
SR-005 는 `assert_no_secrets` 가드가 자산유출을 **"기계적으로 차단"** 하고 **"사람의 기억에
의존하지 않는다"** 고 서술했다. re-review 가 함수를 직접 깨서(SR-006) 이 서술이 **과장**임을
입증했다(5/5 우회, 프로덕션 기본값 no-op, 정상 시세 오차단). 이 문서는 그 서술을 정정한다.

## 1차 방어는 **구조적**이다 (이게 진짜다)
1. `AnalysisContext` 는 사용자 자산 **원본 금액을 담지 않는다.** `AffordabilityResult`(파생값)만 가진다.
2. 각 `Finding` 이 프롬프트에 싣는 값은 한도·부대비용·구속제약 같은 **계산 결과뿐**이다.
   원본 현금·소득은 애초에 finding 에 들어가지 않는다.
3. 이 사실을 `test_파이프라인_프롬프트에_자산금액이_없다` 가 **실제 파이프라인을 돌려** 고정한다.

→ 원본 자산은 **구조적으로** LLM 경로에 도달할 수 없다. 이 방어를 유지하는 것이 최우선이다.

## `assert_no_secrets` 는 **best-effort tripwire**다 (보조 그물)
주 방어가 아니라, 미래에 누군가 UX 목적으로 finding 에 원본 금액을 한 줄 넣는
실수를 **LLM 도달 전에** 잡는 2차 그물이다. 이번에 다음을 강화했다:

| # | re-review 우회 | 조치 | 검증 테스트 |
|---|---|---|---|
| A1 | 억 단위(`3억`) | 단위 정규화 → 300,000,000 으로 비교 | `test_A1_억단위_표기를_잡는다` |
| A2 | 만원 단위(`30000만원`) | 단위 정규화 | `test_A2_만원단위_표기를_잡는다` |
| A3 | 한글 수사(`삼억`) | 한글 한 자리 수사 + 단위 파싱 | `test_A3_한글수사를_잡는다` |
| A4 | 파생값/원본이 finding 에 유입 | fail-loud + 구조적 방어로 LLM 전 차단 | `test_A4_finding에_원본자산이_섞이면_LLM도달_전_차단` |
| A5 | 빈 `forbidden`(프로덕션 기본값) | fail-loud(예외) + affordability 파생 보강 | `test_A5_빈_forbidden_은_fail_loud`, `test_파이프라인은_forbidden을_affordability에서_보강한다` |
| A7 | 정상 시세 13억 오차단 | substring→**값 비교**(토큰 경계) | `test_A7_정상시세_13억은_오차단하지_않는다` |

핵심: 순진한 `str(v) in digits` (전체 프롬프트의 숫자를 이어붙여 부분문자열 검색)를 버리고,
프롬프트를 **금액 값의 집합으로 정규화**(`extract_amounts`)해 **값으로 비교**한다.
그래서 13억(1,300,000,000)이 3억(300,000,000)을 substring 으로 오탐하지 않고(A7),
동시에 억/만/한글 표기 우회를 잡는다(A1·A2·A3).

### fail-loud (A5)
`portfolio_summary` 는 `llm is not None` 인데 검사값(≥100만원)이 하나도 없으면
**조용히 통과하지 않고 `PromptSafetyError` 로 막는다.** "검사할 게 없어서 통과"라는 no-op 제거.
파이프라인은 추가로 `usable_cash_krw` 를 검사값에 자동 보강한다(호출자가 잊어도 무장 유지).

## tripwire 의 한계 (의존 금지)
- 한글 수사는 **한 자리(일~구) + 단위**만 잡는다. "십억"·"이천삼백억" 같은 복합 한글 수는 못 잡는다.
- 공백으로 자릿수를 나눈 표기(`300 000 000`)는 대상이 아니다(무관한 숫자 병합 위험 회피).
- 파생값 자체(월상환액 등)는 **막지 않는다** — 파생값은 원래 LLM 에 가도 되는 값이고, 원본이
  섞이는 것만 구조로 차단한다.
→ 그래서 이건 그물일 뿐이다. **구조(원본을 finding 에 넣지 않기)를 지키는 게 실제 방어다.**
