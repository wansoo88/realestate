# 입지 분석 스코어링·신뢰도 정책 (location-analyst)

> 대상 코드: `backend/app/domain/location/{models,analysis}.py`
> 상위 명세: `docs/02-design/agents/04-location-analyst.md`, `03-valuation-trader.md §D`, `erd.md §0`
>

## 0. 경계 — 무엇을 계산하고 무엇을 안 하나
- 공간쿼리(`ST_Contains` 학구도 포함, `ST_Distance` 역·POI·유해요소 최단거리)는 **리포지토리**가
  수행한다. 이 도메인 계층은 그 결과(포함 여부·거리)를 **점수·근거로 바꾸는 순수 함수**만 갖는다.
- LLM 은 숫자를 만들지 않는다. 계산된 점수·거리를 문장으로 바꾸는 데만 쓴다(README 원칙 1).

## 1. 학군 — 거리가 아니라 학구도 포함 여부
- 배정은 `SchoolFact.in_district`(= `ST_Contains` 결과)로만 인정한다.
- **학구도에 없으면 최근접 학교 거리로 대체하지 않는다.** 배정과 거리는 다른 개념이다.
  학구도 데이터 자체가 없으면 학군 항목을 비우고 `missing` 에 남긴다.
- 학군 배정은 바뀔 수 있어 `as_of`(학구도 기준연도)를 함께 낸다 → 상시 `risks` 에 변경 가능성 명시.
- 학업성취도(%)는 **출처·기준연도가 함께 있을 때만** 사용한다. 없으면 수치를 버리고 `missing` 표기
  (출처 없는 수치 금지 — README 원칙 2).

## 2. 교통 — 실측 역세권 + 신설 노선 호재(신뢰도 강제)
- 역세권 점수는 **현재 운행 중인 역**의 최단거리·노선 수로만 낸다.
- 신설 노선(GTX 등)은 단계별 신뢰도 상한을 강제한다:

  | status | 신뢰도 | 근거 |
  |---|---|---|
  | 계획(미착공) | **0.4** | 착공 전 계획은 지연이 흔하다 |
  | 착공 | 0.6 | |
  | 개통 | 0.9 | |
  | 미상 | **0.3** | 알 수 없으면 가장 보수적으로 |

- **미착공 호재는 점수에 반영하지 않는다**(`HOPE_SCORE_THRESHOLD = 0.5`). 확정 호재처럼 점수를
  올리지 않고, `transit.planned[].confidence` 와 지연 `risks` 로만 남긴다.
  → "GTX 개통 예정"을 확정 호재로 쓰지 않는다.

## 3. 생활 인프라
- 마트·공원·병원 최단거리를 근접 점수로. **병원은 응급실 보유(`has_emergency_room`)를 구분**한다.
  응급실 없는 병원을 응급실처럼 쓰지 않는다.

## 4. 유해요소 — 기피는 제외(가점 상쇄 아님)
- 반경 안에 있으면 '존재'로 본다: 간선도로 소음 50m · 철도 100m · 유해시설 100m · 고압선 150m.
  (이 반경은 **설계 휴리스틱**이다. 규제값이 아니므로 법적 출처를 요구하지 않되 값을 코드에 고정한다.)
- 사용자가 **기피**한 종류가 감지되면 → 후보에서 **제외**(`excluded=True`). 점수를 깎지 않는다.
  파이프라인(`run_mvp_pipeline`)이 예산 초과와 동일하게 하드 제외로 처리한다.
- 기피 목록에 없는 유해요소는 제외하지 않고 감점 + `risks` 경고로만 남긴다.

## 5. 종합 점수·신뢰도
- 있는 항목끼리만 가중 평균: 교통 0.40 · 학군 0.35 · 인프라 0.25.
- 기피 아닌 감점요소는 심각도별 감점(high 15 / medium 8 / low 4), 하한 0.
- 신뢰도 = `0.6 + 0.08 × (가용 항목 수)` → 최대 **0.84**. 실측 거리는 확실하지만 학군 배정 변경
  여지 등을 감안해 상한을 낮게 둔다. 데이터가 하나도 없으면 판단 보류(confidence 0.0).

## 6. 동(棟)별 추정 (F4 §D) — 좌표 기반, 신뢰도 낮게, 금액 환산 금지
- 실거래에 동 정보가 없다(erd.md §0). 동별 가치는 **좌표 사실로 상대 점수만** 낸다.
- `confidence = 0.5`(절대 상한 0.6), `basis = "estimated_from_location"` 강제.
- 상대 점수(0~1)만 내고 **금액으로 환산하지 않는다.** 데이터클래스에 금액 필드가 없다.
  허용: "105동은 101동 대비 역까지 220m 가깝습니다". 금지: "105동이 3천만원 비쌉니다".
- 비교 대상 동이 2개 미만이면 상대 점수를 만들지 않는다.

## 7. 미결(re-arch·re-data 요청 대상)
- **`LocationRepository` 인터페이스 부재.** 현재 `repositories/base.py` 에는
  User/Profile/Map/Job 만 있고, 학구도 포함 판정·역/POI/유해요소 최단거리로
  `LocationFacts` 를 조립해 넘길 계약이 없다. 이게 없으면 `Candidate.location` 이 항상 None →
  location-analyst 는 계속 판단 보류를 낸다.
  → PM 경유로 re-arch 에 `LocationRepository`(+ PostGIS 공간쿼리 구현) 요청 필요.
- 학구도·transit_plan·POI **실데이터 적재**는 re-data 소관(공공 기초자료: 학교알리미·지하철 노선 등).
