# 요구사항 정의서 — 부동산 AI 자문 시스템 (pjt13-realestate)

> 1단계 인터뷰 산출물. 2단계 설계의 입력.

## 1. 서비스 정의
- 유형: AI 자문 웹앱 — 지도 기반 매물 추천 + 근거 리포트 (분석·예측 엔진 내장)
- 주 사용자: 나 개인 (내 자산·소득·대출 한도 기준 실거주/투자 판단). 추후 가족·지인 확장 여지
- 해결할 문제: ① 실거래가·매물·학군·교통·세금·정책이 흩어져 종합 판단이 안 됨 ② 내 자산/대출 한도에 실제로 맞는 후보를 못 고름 ③ 언제 사야 하는지 타이밍 근거가 없음 ④ 같은 단지도 동·층·타입별 가치 차이를 몰라 비싸게 사거나 안 팔리는 물건을 잡음
- 성공 기준(KPI): ① 추천 근거가 납득돼 실제 매수 결정에 사용 ② 지역·매물 조사 시간 며칠→수분 ③ 내 조건(예산·세금·대출·선호)에 맞는 후보만 수천 건에서 5~10건으로 정확히 좁혀짐 ④ (장기) 추천 매물의 사후 수익률이 시장 평균 초과

## 2. 데이터 요구사항
- 소스: 공공 오픈API (국토교통부 실거래가, 공공데이터포털, 부동산원), 포털 매물(호가) 수집 — 네이버 부동산 등, 공공 기초자료 (공시가격, 건축물대장, 학교알리미, 지하철/노선, 인구·세대), 정책·고시 문서 (국토부 보도자료, 지자체 정비사업 고시)
- 규모: 중규모(수십만~수백만)
- 갱신 주기: 매물 준실시간(수시간) / 실거래가 일 1회 배치 / 정책·인프라 주 1회
- 민감정보: 개인 금융정보 (본인 자산·소득·대출한도) + 로그인 계정 — 암호화 저장 필요

## 3. 기술 요구사항
- 클라우드: 자체 서버 (iwinv VPS, `<DEPLOY_HOST>`) — Docker 기반 배포 ※ 실제 IP·계정은 `deploy-target.local.md`(git 제외)
- DB: PostgreSQL + PostGIS (공간쿼리)
- 프론트엔드: React 반응형 웹 (모바일 퍼스트) → React Native 앱 확장
- 백엔드: Python/FastAPI (Docker 기반)

## 4. 운영 & 제약
- 사용자/동시접속 규모: 소수(팀 내)
- 보안·규정: 자산·소득·대출 정보 서버 저장 + 컬럼 암호화(예: pgcrypto/앱단 AES) + 로그인 인증 필수. 공인 IP 노출 서버이므로 root 직접 SSH 금지 → 배포 전용 계정 + 키 기반 접속 + 방화벽/포트 제한. HTTPS 필수. 포털 매물 수집은 개인 비상업 용도 전제 + robots/이용약관 준수 + 수집 속도 제한(rate limit), 공공API만으로도 서비스가 성립하도록 이중화.
- 일정: 2~3개월
- 팀/인수인계: 나 혼자

## 5. 서비스 범위 (도메인)
| 항목 | 확정 내용 |
|---|---|
| 대상 지역 | 수도권 전체 (서울 25개구 + 경기 + 인천) |
| 대상 매물 | 아파트 (재건축 포함). 오피스텔·빌라·상가는 2차 확장 후보 |
| 지도 | 카카오맵 API (주소→좌표 변환, 마커 군집) |
| 모바일 | 모바일 퍼스트 반응형 웹 → React Native 앱 (웹 선행 후 앱 확장) |
| AI 에이전트 | 런타임(웹앱 내 Claude API 분석) + 개발 보조(Claude Code 스킬) 양쪽 |

## 6. 기능 요구사항 (핵심 문제 → 기능 매핑)
| # | 핵심 문제 | 기능 요구사항 | 담당 에이전트 |
|---|---|---|---|
| F1 | 정보가 흩어져 종합 판단 불가 | 지도 + 매물 리스트 통합 화면. 단지 선택 시 시세·학군·교통·정책·세금이 한 화면에 종합된 근거 리포트 | `portfolio-advisor` |
| F2 | 내 자산/대출 한도에 맞는 후보 선별 불가 | 자산·소득·기존 대출·보유주택 수 입력 → 취득세·보유세·LTV/DSR 반영 **실구매 가능 금액** 산출 → 그 이하 매물만 필터 | `finance-tax-advisor` |
| F3 | 매수 타이밍 판단 불가 | 전세가율·미분양·입주물량·금리·정책 변화 기반 지역별 매수 타이밍 신호 + "지금 vs 대기" 근거 | `market-timing-analyst`, `policy-researcher` |
| F4 | 동·층·타입별 가치 차이 모름 | 같은 단지 내 동/층/향/타입별 실거래 편차 분석, 적정가 밴드, 호가–실거래 갭, 환금성 점수 | `valuation-trader` |
| F5 | 선호/기피 반영 | 선호(학군·역세권·신축·대단지 등)와 **기피(대로변 소음·1층·재건축 리스크 등)** 조건 입력 → 가중 스코어링 및 제외 필터 | `location-analyst`, `risk-auditor` |
| F6 | 근거 없는 추천은 신뢰 못 함 | 모든 추천에 **"왜 이 매물인가"** 근거를 데이터 출처와 함께 서술. 반대 근거(리스크)도 병기 | `portfolio-advisor` |

### 런타임 전문가 에이전트 로스터
`listing-researcher`(매물 리서처) · `location-analyst`(지역) · `finance-tax-advisor`(세금·대출) · `valuation-trader`(매매) · `policy-researcher`(정책) · `market-timing-analyst`(타이밍) · `risk-auditor`(리스크) · `portfolio-advisor`(종합 자문)
> MVP는 매물 리서처 · 세금대출 · 매매 · 지역 · 종합자문 **5종**으로 시작, 나머지 3종은 2차. (2단계에서 확정)

## 7. 비기능 요구사항
- **모바일 퍼스트**: 폰 기준 설계 후 데스크톱 확장. 지도 한 손 조작, 리스트↔지도 전환, 터치 타깃 44px 이상.
- **성능**: 지도 이동 시 화면 범위 매물 조회 1초 이내(PostGIS 공간 인덱스). AI 리포트 생성은 비동기 + 진행 표시.
- **비용**: 개인 서버 운영이므로 Claude API 호출 비용이 주 변동비 → 분석 결과 캐싱 필수.
- **면책**: 투자 권유가 아닌 개인 판단 보조 도구임을 리포트에 고지.

## 8. 도메인 리스크 (설계 시 반드시 반영)
- 공공 오픈API에는 현재 호가가 없고 과거 체결가만 존재 → 포털 수집 필요하나 약관 이슈. **공공API만으로도 서비스가 성립하도록 이중화**.
- 실거래가 신고는 최대 30일 지연 → "현재 시세"는 항상 추정치임을 UI에 명시.
- 공인 IP VPS 노출 → `root` 직접 SSH 금지, 배포 전용 계정 + 키 기반 접속 + 방화벽.
